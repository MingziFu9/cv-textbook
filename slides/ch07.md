# 7.1 视频就是一串图片

## 帧、帧率、分辨率
![从行车视频每隔 3 秒取出的 4 帧](images/frames.jpg)
- **帧**：一张图，本例 640×360
- **帧率**：每秒几帧，本例 25 fps
- 时长 = 总帧数 ÷ 帧率 = 300 ÷ 25 = 12 秒

::: notes
算一算：一帧 640 × 360 × 3 = 691 200 个数，约 0.66 MB，300 帧约 198 MB，可 mp4 只有约 4 MB，因为相邻帧大部分一样，视频经过了压缩。手翻书的比喻帮助学生理解帧。
:::

## 视频文件和视频流
| 来源 | 打开方式 |
|---|---|
| 视频文件 | `cv2.VideoCapture("a.mp4")` |
| 电脑摄像头 | `cv2.VideoCapture(0)` |
| 网络视频流 | `cv2.VideoCapture("rtsp://…")` |

- 文件可以慢慢处理；**视频流是实时的**
- 辅助驾驶面对的是视频流

# 7.2 用 OpenCV 处理视频

## 读视频：一帧一帧地取
```python
cap = cv2.VideoCapture("../data/videos/highway_12s.mp4")
while True:
    ok, frame = cap.read()       # 读完了 ok 是 False
    if not ok:
        break
    # frame 就是一张普通图片
cap.release()
```

## 写视频
```python
fourcc = cv2.VideoWriter_fourcc(*"mp4v")
writer = cv2.VideoWriter("out.mp4", fourcc, fps, (w, h))
writer.write(frame)
writer.release()
```
- 尺寸写 **(宽, 高)**，和 shape 顺序相反
- 每帧大小必须一致，否则得到空文件
- 300 帧按 50 fps 写 → 6 秒，2 倍速

## 实时：每帧 40 毫秒
- 25 fps → 每帧只有 1000 ÷ 25 = **40 毫秒**
- 编者 CPU 检测一帧 0.1～0.3 秒，跟不上
| 提速办法 | 代价 |
|---|---|
| 跳帧 | 反应慢一点 |
| 缩小尺寸 | 远处小目标难找 |
| 选小模型 | 精度略低 |
| GPU、AI 芯片 | 成本 |

# 7.3 目标跟踪：给每个目标发号码牌

## 检测不够，还要跟踪
- 检测器只知道“这帧有 3 个框”
- 跟踪：给每个目标发号码牌（**ID**）
- 开了多远？在变近还是变远？
- 路口过去几辆车？（每个号码只数一次）
- 行人是不是正在走进车道？

## 跟踪器每帧做三件事
- ① **预测**：按过去的运动推算这帧在哪
- ② **配对**：预测位置和检测框按交并比配对
- ③ **记住**：没配上的号码牌先留几帧
- 比喻：点名，请假的先不划掉

::: notes
常用跟踪器：ByteTrack（低置信度的框也拿来配对）、BoT-SORT（外观特征 + 相机运动补偿）。本书所用 Ultralytics 版本默认 TrackTrack，“记住” 30 帧。都是“预测 + 配对 + 记住”的思路。
:::

## 用 Ultralytics 跟踪
```python
for r in model.track(VIDEO, stream=True, persist=True,
                     classes=[2, 5, 7], verbose=False):
    if r.boxes.id is None:       # 这一帧没跟踪到
        continue
    print(r.boxes.id.int().tolist())
```
- `persist=True`：记住上一帧的号码牌

# 7.4 跟踪的用法：计数、闯入、变近

## 有了号码牌能做什么
| 用法 | 做法 | 场景 |
|---|---|---|
| 越线计数 | 中心点跨线，每号只算一次 | 车流量、客流 |
| 区域闯入 | “脚下”点进入多边形 | 行人进车道 |
| 变近变远 | 比较 1 秒前后框面积 | 前车碰撞预警 |
| 停留时间 | 连续出现多少帧 | 违停、排队 |

## 区域闯入：看“脚下”
![行人视频中的区域闯入](images/zone.jpg)
- `cv2.pointPolygonTest(zone, foot, False) >= 0`
- 脚下 = 框底边中点
- 框中心在腰部，会“提前进去”

## 变近还是变远
- 倍数 = 现在面积 ÷ 1 秒前面积
- 大于 1.2 变近，小于 0.8 变远
- 黑车：11 779 ÷ 15 726 ≈ 0.75 → 变远
- 刚进画面：4168 → 15 666，倍数 3.76？
- 贴着边缘的框**先不判断**

::: notes
黑车 3.76 倍是因为从画面右边“钻进来”，只露出车头，框自然越来越大。真实的前车碰撞预警算“碰撞时间”，小于 2～3 秒报警。
:::

# 7.5 动作识别：动作是一段时间

## 姿态估计：17 个人体关键点
![俯卧撑视频中的人体关键点](images/pose.jpg)
- `yolo26n-pose.pt`，COCO 17 个点
- 5、6 左右肩；7、8 肘；9、10 腕
- 肩-肘-腕三点 → **肘角**

## 只看一帧够不够
![5 个俯卧撑的肘角曲线](images/angles.png)
- 肘角 120 度：在压下还是在撑起？
- 一个俯卧撑 = 曲线上的一个“谷”
- **动作识别**要看一串帧

## 两个门槛 + 连续几帧
- 撑起状态，降到 **100 度**以下 → 压下
- 压下状态，回到 **140 度**以上 → 撑起，计数 +1
- 两个门槛之间是**缓冲区**，抖动不误数
- 连续 3 帧满足才切换

::: notes
实验 7-3 的俯卧撑视频由 Ultralytics 示例拼成 5 次，右臂角度 160 → 62 度，计数正好 5 个。
:::

## 动作识别的三种做法
| 做法 | 输入 | 例子 |
|---|---|---|
| 关节角度规则 | 关键点 | 俯卧撑、深蹲计数 |
| 骨架序列分类（ST-GCN） | 一串关键点 | 摔倒、交警手势 |
| 视频模型（I3D） | 一段视频 | 打电话、抽烟 |

- 从上到下：越来越强，也越来越贵

## 驾驶员分心与疲劳提醒
| 危险行为 | 线索 |
|---|---|
| 低头看手机 | 鼻子和两肩的位置 |
| 长时间转头 | 鼻子偏离两肩中线 |
| 疲劳、打瞌睡 | 闭眼时间比例、打哈欠 |
| 打电话、抽烟 | 手在耳边、手里的物体 |

- 关键是**持续时间**：连续 2 秒以上才提醒

## 辅助，不是替代
- 驾驶员监测只能**提醒**
- 驾驶员始终对驾驶负责
- 车内摄像头拍到人脸 → **敏感个人信息**
- 采集、保存要遵守《个人信息保护法》

::: notes
欧盟从 2024 年起要求新车配备驾驶员疲劳和注意力提醒，国内很多新车型也已标配。实验 7-4 只录自己，不要录别人。

## 视频内容理解（了解）
| | 专门的视觉程序 | 多模态大模型 |
|---|---|---|
| 擅长 | 实时、精确的数字 | 开放问题：发生了什么 |
| 速度 | 每帧几十毫秒 | 一段几秒到几十秒 |
| 可靠性 | 错了能查原因 | 可能“编造” |
| 适合 | 车上实时提醒 | 事后写摘要 |

## 常见报错
| 报错 | 意思 |
|---|---|
| 视频 0 KB / 打不开 | 尺寸不一致或忘了 `release()` |
| `cap.read()` 一开始就 False | 路径不对 |
| `'NoneType' … attribute 'int'` | 这帧没跟踪到，id 是 None |
| `No module named 'lap'` | `pip install lap` |
| 号码牌接着上段视频编 | 换视频重新加载模型 |
