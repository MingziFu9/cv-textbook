# 9.1 视觉应用的“配方”

## 六个行业，一样的零件
| 行业 | 用到的步骤 | 对应章 |
|---|---|---|
| 安防监控 | 检测人 → 跟踪 → 越线 / 区域 | 5、7 |
| 辅助驾驶 | 检测 → 分割 → 距离 → 跟踪 → 提醒 | 5～7 |
| 医疗影像 | 分类 → 检测或分割病变 | 4、6 |
| 工业质检 | 预处理 → 检测缺陷 → 测尺寸 | 2、3、5 |
| 智慧零售 | 检测商品 → 分类 → 计数 | 4、5、7 |
| 增强现实 | 找标记 → 单应性矩阵 → 贴图 | 9 |

## 拆解一个应用：三个问题
- **输入是什么？** 照片、视频、多摄像头
- **要回答什么？** 是什么、在哪里、轮廓、去哪、在做什么
- **答案怎么用？** 显示、报警、计数还是控制机器
- 用得越“重”，准确率和速度要求越高

## 同一个任务，要求差很多
| 场合（检测行人） | 更看重 | 速度 |
|---|---|---|
| 商场客流统计 | 便宜 | 几秒一次 |
| 小区周界报警 | 精确率召回率都高 | 1 秒内 |
| 辅助驾驶行人提醒 | 召回率，误报不能多 | 每秒十几帧 |
| 医疗影像筛查 | 召回率，医生确认 | 不急 |

- **机器负责提醒，人负责决定**

## 本书的助手在哪一层
| | 本书的助手 | 量产车驾驶辅助 |
|---|---|---|
| 摄像头 | 一张照片或一段视频 | 6～11 个 + 雷达 |
| 速度 | CPU 约 0.2 秒一张 | 专用芯片几十帧 |

# 9.2 增强现实

## 把虚拟的东西贴到现实里
| 例子 | 叠加什么 | 先看懂什么 |
|---|---|---|
| AR 步行导航 | 路面箭头 | 地面、手机朝向 |

- 核心问题：贴在**哪里**、变成**什么形状**

## 标记码 ArUco
- **好找**：黑色粗边框，轮廓一找就到
- **认号码**：4×4 格子编码一个号
- **分方向**：不对称，知道哪个是左上角
- **四个角很准** → 算出平面的样子
- `DICT_4X4_50`：生成和找码用同一本“密码本”

## 单应性矩阵：四对点决定一切
```python
H = cv2.getPerspectiveTransform(纸上四角, 照片里四角)
warped = cv2.warpPerspective(纸, H, (照片宽, 照片高))
```
- 纸平放在路面上 → 照片里变成梯形
- 3×3 的**单应性矩阵** H 描述这个变换
- 四对对应点就能算出 H

::: notes
算一算：只缩放 2 倍、平移 (100, 50) 时，H 的前两行是 [2 0 100]、[0 2 50]，第三行 [0 0 1]。纸上 (10, 20) → (120, 90)。透视时第三行不再是 (0, 0, 1)，还要除以随位置变化的数，这就是“近大远小”的来源。
:::

## 没有标记码怎么办
- **找平面**：跟踪关键点，算出地面

# 9.3 场景重建（了解）

## 从照片到三维世界
| 方法 | 输入 | 输出 |
|---|---|---|
| 单目深度估计 | 一张照片 | 深度图（第 6 章） |
| 多视角重建 SfM | 拍一圈照片 | 点云、三维模型 |
| NeRF、3DGS | 一段视频 | 自由转视角 |
| 鸟瞰图、占用网络 | 车上多摄像头 | 俯视地图、占用空间 |

::: notes
多视角重建：找关键点、配对、反推相机位置和三维点，常用 COLMAP，用于文物数字化、电商 3D 展示。NeRF（2020）用神经网络记住每个点的颜色和密度；三维高斯泼溅（2023）用大量半透明椭球，画得更快。BEV 把多摄像头统一成俯视图；占用网络把空间切成小方块判断有没有被占。
:::

# 9.4 看懂文字与“看图说话”

## 文字识别 OCR
- 先**检测**文字在哪，再**识别**是什么字
- 车牌识别、证件识别、拍照翻译、限速牌
- PaddleOCR（百度飞桨）：中文效果好
- 车牌、身份证号是**个人信息**

## 多模态大模型：直接问图
- 上传照片：“前方有哪些需要注意的？”
- **慢**：几秒，行车提醒要零点几秒
- **会编**：说出图里没有的东西
- **难检查**：文字回答难量化
- 快和准用专门模型，解释原因交给大模型

# 9.6 让模型跑得更快

## 速度怎么算
- 每秒张数 = 1000 ÷ 每张毫秒数
- 检测 26 + 分割 61 + 深度 128 = **215 毫秒**
- 1000 ÷ 215 ≈ **4.7 张/秒**
- 测速：先**热身**，再**多跑几次取平均**

::: notes
算一算：车速 60 千米/小时约每秒 16.7 米，每 215 毫秒车已经开出约 3.6 米。这就是车上要用专用芯片的原因。
:::

## 缩小输入尺寸
| imgsz | 每张 | 每秒 | 找到目标 |
|---|---|---|---|
| 640 | 26.5 毫秒 | 37.8 张 | 8 |
| 480 | 17.2 毫秒 | 58.0 张 | 8 |
| 320 | 12.2 毫秒 | 82.1 张 | 6 |

- 320：两辆远处小车漏掉，公交车认成轿车

## 四种提速办法
| 办法 | 代价 |
|---|---|
| 选小模型（n 号） | 精度略低 |
| 缩小输入尺寸 | 远处小目标易漏 |
| 换推理格式：ONNX、TensorRT、OpenVINO | 多一步导出 |
| **量化**：32 位 → 8 位整数 | 精度可能降一点 |

::: notes
`model.export(format="onnx")` 生成 yolo26n.onnx，再 YOLO("yolo26n.onnx") 用法完全一样。实验 9-4 第 4 步（ONNX 测速）待实测，请教师课前先跑一遍。
:::

# 9.7 伦理与法规

## 人脸、车牌、行踪都是个人信息
- 《个人信息保护法》（2021.11.1）
- 清楚的**人脸**：生物识别，**敏感个人信息**
- **车牌**能关联车主
- 行车视频 + 时间位置 → **行踪轨迹**
- 公共场所采集：为公共安全所必需，设提示

## 《人脸识别技术应用安全管理办法》
- 2025 年 6 月 1 日施行
- 不得把刷脸作为**唯一**验证方式
- 公共场所安装要必需，并设显著提示
- 私密空间内部**不得安装**
- 存储达 10 万人要备案

## 汽车里的数据
- 车内处理：确有必要才向车外提供
- **默认不收集**
- 精度范围适用：够用就好
- **脱敏处理**：匿名化、去标识化
- 车外人脸、车牌视频属于**重要数据**

::: notes
《汽车数据安全管理若干规定（试行）》2021 年 10 月施行。这就是实验 3-4 要给行车照片打码的原因。2025 年 4 月工信部要求车企规范驾驶辅助宣传，不得夸大。
:::

## 深度合成与算法偏见
- AI 换脸、假人像：本人同意 + 标识
- **偏见**：对某些群体系统性地表现更差
- 来源：训练照片多是白天、晴天、欧美城市
- 夜间、雨天、电动车多的路口表现下降
- 检查：**分组评估**，按天气、时间、人群分开算

## 一张自查清单
- **拍了谁？** 能不能少拍、拍模糊
- **存了什么？** 只存结果，不存原图
- **给了谁？** 会不会传到网上
- **对谁不公平？** 哪类人、哪种场景更差
- **错了怎么办？** 谁最终判断，有没有“仅供参考”

## 新手常踩的坑
| 坑 | 怎么避免 |
